# Operations runbook

This runbook covers the Day 8 backend MVP: PostgreSQL, one-shot migrations,
the FastAPI service, and the durable worker. Commands assume they are run from
the project root.

## Service responsibilities

| Service | Responsibility | Durable state |
|---|---|---|
| `postgres` | Source of truth and concurrency boundary | Named volume `postgres_data` |
| `migrate` | Run `alembic upgrade head` with the DDL-capable role | None; exits `0` |
| `api` | Authenticate, validate, accept commands, and serve queries | None outside PostgreSQL |
| `worker` | Lease outbox work, call the provider, and commit results | None outside PostgreSQL |

The API and worker use the restricted runtime database role. Only the migrate
service uses the DDL-capable migrator role. The bootstrap superuser is needed
only when PostgreSQL initializes an empty volume.

## Normal start, observation, and stop

Start or update all services:

```bash
docker compose up --build --detach
docker compose ps --all
```

The expected steady state is:

- `postgres`: healthy
- `migrate`: exited with code `0`
- `api`: healthy
- `worker`: running

Follow logs without changing state:

```bash
docker compose logs --follow --tail=100 api worker
```

Stop processes while preserving the database volume:

```bash
docker compose down
```

Restart one stateless service:

```bash
docker compose restart api
docker compose restart worker
```

## Health and traffic decisions

```bash
curl --fail-with-body --include http://127.0.0.1:8000/health/live
curl --fail-with-body --include http://127.0.0.1:8000/health/ready
```

Use liveness to decide whether to restart the API process. Use readiness to
decide whether to route traffic. Readiness performs a two-second-bounded
PostgreSQL `SELECT 1`; a DB outage should produce `503` while liveness remains
`200`.

## Migration workflow

The two URLs have different jobs:

- `CHAT_MIGRATION_DATABASE_URL` uses `enterprise_chat_migrator` for DDL.
- `CHAT_DATABASE_URL` uses `enterprise_chat_app` for runtime DML.

Never give the API or worker the migrator URL.

Inspect and apply migrations from the host:

```bash
uv run alembic heads
uv run alembic current
uv run alembic upgrade head
uv run alembic current
uv run alembic check
```

Run the Compose migration job again:

```bash
docker compose run --rm migrate
```

Preview SQL without applying it:

```bash
uv run alembic upgrade head --sql
```

After intentionally changing SQLAlchemy metadata, create and review a
migration:

```bash
uv run alembic revision --autogenerate -m "describe the schema change"
uv run ruff format migrations
uv run ruff check --fix migrations
uv run alembic upgrade head --sql
uv run alembic upgrade head
uv run alembic check
```

Do not treat autogenerated migration code as trusted output. Review table
schema, constraint names, tenant columns, foreign keys, indexes, grants,
downgrade order, and accidental drops. Downgrades may destroy data; exercise
them only against disposable local/test databases.

## Test workflow

Fast checks, which exclude integration tests by project configuration:

```bash
uv lock --check
uv sync --frozen --all-groups
uv run ruff format --check src tests migrations
uv run ruff check src tests migrations
uv run mypy src tests migrations/env.py migrations/versions
uv run pytest -q
```

Real PostgreSQL verification:

```bash
docker compose up --detach postgres
uv run alembic upgrade head
uv run pytest -m integration -q
uv run alembic check
```

`alembic check` must end with `No new upgrade operations detected.` A reported
operation means model metadata and committed migrations disagree.

## How durable processing recovers

One accepted turn writes the conversation update, user message, queued run,
idempotency receipt, and outbox event in one transaction. The worker then:

1. Selects one due event with `FOR UPDATE SKIP LOCKED`.
2. Increments its attempt counter and records a unique lease token/expiry.
3. Moves a queued run to running and commits that short transaction.
4. Calls the provider outside every database transaction with a timeout.
5. In a new short transaction, either:
   - appends the assistant message, advances the conversation, succeeds the
     run, and marks the event published;
   - releases the lease and delays the event for retry; or
   - records a terminal safe failure and marks the event published.

The default lease is 60 seconds and the provider timeout is 30 seconds. The
lease must always be longer than the timeout. A lease token fences late work:
an expired worker cannot overwrite a result owned by a newer worker.

Transient errors and timeouts use exponential backoff with jitter, capped by
`CHAT_WORKER_MAX_BACKOFF_SECONDS`, for at most
`CHAT_WORKER_MAX_ATTEMPTS` provider calls. A reclaimed lease already beyond
that limit is failed before another provider call. Unknown provider exception text is neither
persisted nor returned to clients; a production adapter should emit sanitized
telemetry without prompts, credentials, or raw sensitive payloads.

At-least-once processing means a provider call can happen more than once if a
process dies after the external call but before committing its result. A real
provider adapter should send the agent-run ID as a provider idempotency key
when the provider supports it.

## Incident: readiness is `503`

1. Confirm container state and recent logs:

   ```bash
   docker compose ps --all
   docker compose logs --tail=200 postgres migrate api
   ```

2. Confirm PostgreSQL accepts connections inside its container:

   ```bash
   docker compose exec -T postgres sh -c \
     'pg_isready --host=127.0.0.1 --username="$POSTGRES_USER" --dbname="$POSTGRES_DB"'
   ```

3. Confirm migrations reached the head:

   ```bash
   uv run alembic current
   uv run alembic heads
   ```

4. If the DB and migration are healthy, verify `CHAT_DATABASE_URL` contains
   the runtime user, correct password/host/database, and the
   `postgresql+asyncpg` driver. Do not print the secret URL into shared logs.

5. Restart only the stateless API after fixing configuration:

   ```bash
   docker compose restart api
   ```

## Incident: migration job failed

1. Read its complete log before rerunning it:

   ```bash
   docker compose logs migrate
   ```

2. Verify the migrator URL and compare current/head revisions:

   ```bash
   uv run alembic current
   uv run alembic heads
   ```

3. Fix the migration or configuration, review offline SQL, and run the
   one-shot job again:

   ```bash
   uv run alembic upgrade head --sql
   docker compose run --rm migrate
   ```

Never stamp a revision merely to silence an error. `alembic stamp` changes the
version marker without applying schema changes.

## Incident: runs stay queued or running

Inspect worker logs and restart the stateless process if needed:

```bash
docker compose logs --tail=200 worker
docker compose restart worker
```

Inspect the durable queue without exposing message content:

```bash
docker compose exec -T postgres sh -c '
  psql --no-psqlrc --username="$POSTGRES_USER" --dbname="$POSTGRES_APP_DATABASE" \
    --command="SELECT event_type, attempt_count, available_at, lease_expires_at, published_at FROM chat.outbox_events ORDER BY occurred_at;"
'
```

Interpretation:

- `published_at IS NOT NULL`: the event reached a terminal outcome.
- Future `available_at`: a transient failure is waiting for backoff.
- Future `lease_expires_at`: a worker currently owns the attempt.
- Expired lease with no publication: another healthy worker will reclaim it.
- Attempt count at the configured maximum: inspect the associated run; it
  should become `failed` with a safe message.

Do not clear leases or edit run status manually during a normal recovery.
Restart the worker and let lease expiry/fencing preserve correctness.

## Incident: client did not receive the turn response

The database commit may have succeeded even when the network response was
lost. Retry the exact POST using the same tenant, user, conversation,
`Idempotency-Key`, and JSON content.

- If the first commit succeeded, the API returns the original IDs with
  `replayed: true`.
- If it did not commit, the retry creates the turn once.
- If any fingerprinted input changed, the API returns `409` instead of
  guessing.

Never solve an unknown outcome by immediately generating a new idempotency
key; that explicitly asks the server to create a second turn.

## Incident: run failed terminally

The polling endpoint exposes only a safe failure message. Raw provider errors
are not part of the public contract. After the maximum attempts, the existing
idempotency key continues to return the same original run; it does not create
new work.

This MVP has no administrative redrive endpoint. After correcting the cause,
the user may submit a new turn with a new idempotency key. Do not mutate
terminal rows directly.

## Local database reset

PostgreSQL initialization scripts run only when the data directory is empty.
Changing passwords in `.env` does not update roles inside an existing volume.

For a disposable local environment only, the following deletes all Day 8
database data and recreates roles/schema on the next start:

```bash
docker compose down --volumes
docker compose up --build --detach
```

This is destructive and is not a credential-rotation procedure. Production
credentials must be rotated with audited PostgreSQL role changes and a secrets
manager.

## JWT production checklist

- Set `CHAT_ENVIRONMENT=staging` or `production`.
- Set `CHAT_AUTH_MODE=jwt`; development headers are then ignored.
- Set `CHAT_ALLOW_INSECURE_DEVELOPMENT_AUTH=false` (the fail-closed default).
- Keep `CHAT_PROVIDER_MODE=disabled` until a real provider adapter is wired;
  deployed environments reject `echo`.
- Use `RS256` or `ES256`; deployed environments reject `HS256`.
- Inject only the verification public key into `CHAT_JWT_KEY` through the
  deployment secret manager.
- Match configured issuer and audience exactly.
- Require the identity provider to issue `exp`, `iat`, `iss`, `aud`, `sub`,
  and `tenant_id`; `sub` and `tenant_id` must be UUID strings.
- Terminate TLS before the API and never log bearer tokens.
- Keep the migrator credentials out of API and worker containers.

## Production boundary and next work

`EchoChatProvider` is deterministic local/test behavior, not a real AI
integration. Replace and inject it in worker composition with an adapter that
classifies transient vs terminal provider failures, applies provider-specific
timeouts and idempotency, and does not expose raw errors.

Redis/WebSockets, RAG, embeddings, tool execution, and a frontend are outside
this backend MVP. Polling is the current reliable delivery contract. Before a
public production launch, also supply platform-specific TLS, secret rotation,
backup/restore drills, metrics/traces/alerts, capacity tests, and deployment
automation. Tenant isolation currently relies on authenticated actor context,
tenant-scoped queries, composite constraints, and the restricted runtime role.
PostgreSQL row-level security is not enabled by this project; assess and add it
as defense in depth before a hostile shared-database deployment.
